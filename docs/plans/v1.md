# Version 1 implementation plan

- Goal: select a display, camera and microphone, record a full-screen MP4 with a movable camera bubble, stop globally, and reveal the saved file.
- Files: SwiftUI/AppKit app in Sources/MacVideos; deterministic settings, device selection and output naming in Sources/MacVideosCore; Tests; Xcode project/project.yml; README, AGENTS.md, CODING.md, docs/youtube-upload-plan.md and local scripts. Shared checkout remains untouched.
- Approach: macOS 27 (this Mac is 27.2), ScreenCaptureKit SCRecordingOutput for H.264 MP4 and microphone audio, AVFoundation device discovery and camera preview. Exclude this application's windows with an explicit exception for its bubble. Use Carbon registered hotkey rather than accessibility/event monitoring. No external runtime packages, server or CI. Avoid a custom AVAssetWriter pipeline because the OS already supplies synchronized recording.
- Risks: user must grant camera/microphone/screen permissions; actual camera/display/audio capture needs an interactive smoke test. Files stay local, folder access is explicitly chosen, no network/auth/keys. Lost devices and capture failures must surface and stop safely. No production changes.
- Tests: xcodebuild build and hostless XCTest tests for filename uniqueness, settings persistence, stale device selections and display geometry. Local application launch; permission-dependent capture only when existing consent allows it. Review source for filter, stop/finalization and failure paths before PR, rerun checks on final head before merge.
- Size: one native app and a small pure core, a single implementation pass with build/review corrections.
- Known turn-backs: no existing review-lessons or product code.
- Execution: all work performed directly in Codex, per handoff instruction; no Claude-only agents/skills.
